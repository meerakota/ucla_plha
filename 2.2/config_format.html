Config File Format#

ucla_plha uses a Javascript Object Notation (JSON) input file to configure the analysis, and uses JSON Schema to validate user inputs. Example config files are provided in the Examples section of this documentation, and the schema is defined by the ucla_plha_schema.json file in the src/ucla_plha directory of the GitHub repository. We validate that the data types are correct and that all required fields have been specified.

We thought about using a more human-readable input file format such as YAML, but decided to use JSON instead since our code is intended for HPC applications. Both JSON and YAML are human readable, but JSON is better for machine-parsing, and we prioritized that in our code.

Distance and other options#

"constraints" accepts "dist_cutoff" (km; applied to Rjb if a ground motion model uses Rjb, otherwise to Rrup), "m_min", "truncation_level" (upper truncation of the ground motion distribution in standard deviations; the USGS NSHM uses 3; default none), "rupture_rx": "gc2" (default) takes Rx and Ry0 of a fault rupture from the GC2 coordinates of Spudich and Chiou (2015) of the whole rupture, as in the NGA-West2 and NGA-West3 flatfiles (Rx1 = Rx minus the horizontal width of the segment with the smallest Rrup), "closest_section" takes Rx and Rx1 from the segment with the smallest Rrup, as nshmp-lib does, and "minimum" takes the minimum over the segments (earlier versions; because Rx is signed, this is the most footwall-side segment of the rupture); with the last two, Ry0 is the minimum over the segments. "triangle_frame": "local" (default) computes the Rjb and Rrup of the fault triangles in a projection on a sphere centred on the site, so that they are measured along the Earth’s surface and Rrup >= Rjb, and "geocentric" uses straight lines in Earth-centred Cartesian coordinates (earlier versions; Rrup < Rjb for most ruptures beyond about 100 km). "output": {"psha": {"source_model_hazard": true}} adds the hazard curve of each source model.

"ngl_smt_2024" treats the peak acceleration of an earthquake as the same in all layers of the profile ("pga_uncertainty": "shared", the default). The probability of profile manifestation is computed for a given magnitude \(M\) and PGA,

\[P(FS < FS_L \mid M, PGA) = 1 - \prod_j \left[1 - P_{MT,j}\, \Phi\left(\frac{\ln FS_L - \mu_{\ln CRR,j}(M, PGA) + \ln CSR_j(M, PGA)}{0.44}\right) P_{S,j}\, K_{sat,j}\right]^{t_j / t_c}\]

(with the magnitude scaling factor of that PGA), and integrated over the distribution of \(\ln PGA\) of the earthquake, truncated as in the PSHA ("constraints": {"truncation_level": ...}; untruncated if it is not given). The NGL SMT model itself does not treat the ground motion uncertainty. Versions 2.x and earlier included the PGA uncertainty in each layer separately (\(\sigma = \sqrt{0.44^2 + \sigma_{\ln PGA}^2}\), magnitude scaling factor of the median PGA, untruncated) before the product over the layers, as if each layer had an independent PGA, which gives higher probabilities (about 5% to 15% in relative terms for single earthquakes); "pga_uncertainty": "per_layer" reproduces those results exactly.

With "shared", the integration uses a grid of the rates of the ground motions of the site over magnitude and \(\ln PGA\) ("pga_integration": "grid", the default; ucla_plha.pga_grid), built once for the site and shared by the liquefaction models conditioned on PGA, so that the cost of a liquefaction model is small. With the default "pga_grid" parameters (bins of 0.1 in \(\ln PGA\) from 1e-4 g to 10 g, magnitude nodes every 0.05, and histogram nodes of the mean and standard deviation of \(\ln PGA\) of the earthquakes every 0.05 and 0.005), the hazard curves agree with an exact integration within about 2e-4 (relative). The disaggregation uses per-earthquake probabilities from the grid nodes. "pga_integration": "quadrature" integrates each earthquake with Gauss-Legendre quadrature (slow; for verification).

"boulanger_idriss_2016" and "moss_et_al_2006" are also computed conditioned on the peak acceleration ("pga_uncertainty": "conditional", the default),

\[P(FS < FS_L \mid M, PGA) = \Phi\left(\frac{\ln FS_L - \mu_{\ln CRR} + \ln CSR(M, PGA)}{\sigma_{\ln CRR}}\right)\]

with the model uncertainty only (\(\sigma_{\ln CRR}\) = 0.20 and 1.632 / 7.177), integrated over the ground motion distribution of the earthquake with the truncation of the PSHA, on the same magnitude \(\times\) PGA grid as "ngl_smt_2024" (one grid per site for these models). For Boulanger and Idriss (2016), PGA enters only through CSR, so without truncation this is the closed form of earlier versions, \(\Phi\left((\ln FS_L - \mu_{\ln CRR} + \mu_{\ln CSR}) / \sqrt{0.20^2 + \sigma_{\ln PGA}^2}\right)\). For Moss et al. (2006), \(r_d\) (which depends on \(a_{max}\)) and the \(\Delta q_c\) adjustment of the CRR (\(x_1 \ln CSR + x_2\), for \(R_f > 0.5\%\)) are evaluated at the conditioned PGA instead of the median PGA; \(\Delta q_c\) is not allowed below 0 (their Eq. 18 bounds the fines adjustment to \(R_f\) of 0.5 to 5% as a suppression of liquefiability; \(x_1 \ln CSR + x_2 < 0\) only for \(CSR < e^{-3.84} = 0.021\), outside their data); and the CSR is not divided by the duration weighting factor \(DWF = 17.84 M_w^{-1.43}\) (with any "pga_uncertainty"), because their Eq. 20 and 21 have their own magnitude term (\(-0.848 \ln M_w\)) and are compared with the CSR of the event (the note to Eq. 21: it “produces results for the input magnitude”, whereas their Figs. 6 and 10 are for \(M_w\) 7.5, CSR*; and the CSR of the case histories in their Table 1 is \(0.65\, a_{max} (\sigma_v / \sigma'_v)\, r_d\), not CSR / DWF). Earlier versions divided by the DWF as well, which double counted the magnitude effect (FS higher by the DWF: about 1.4 at \(M_w\) 6, 1.1 at 7, 0.91 at 8); the 2.x Moss et al. (2006) results, which divided CSR by the DWF, can’t be reproduced with this version (a config with "duration_weighting" is rejected). "pga_uncertainty": "closed_form" gives the untruncated closed forms of earlier versions: exactly for Boulanger and Idriss (2016), and for Moss et al. (2006) with \(r_d\) and \(\Delta q_c\) at the median PGA but without the DWF. The \(r_d\) of Moss et al. (2006) (from Cetin et al. 2004) decreases with \(a_{max}\) to the lower limit 0.2 at about 2.5 to 3.5 g and jumps to the upper limit 1.0 at about 3.5 to 4 g (its denominator changes sign), so with "conditional" \(r_d\) is evaluated with \(a_{max}\) at most "rd_amax_cap" (default 1 g; null for no limit; \(r_d\) above the cap is \(r_d\) at the cap). "closed_form" (\(r_d\) of the median PGA) has no cap. plha.DEFAULT_PGA_UNCERTAINTY holds the default treatment of each model.

"cetin_et_al_2018" includes only the model uncertainty (\(\sigma_\varepsilon = 2.95\)) by default. With "parameter_uncertainty": true, the input parameter uncertainty of Cetin et al. (2018b) is added, \(\sigma_{tot}^2 = \theta_7 \sigma_{input}^2 + \sigma_\varepsilon^2\) with \(\theta_7 = 0.392\) and \(\sigma_{input}^2 = \theta_6^2 \delta_{CSR}^2 + \sigma_{N_{1,60}}^2 (1 + \theta_1 FC)^2 + \sigma_{FC}^2 (\theta_1 N_{1,60} + \theta_4)^2 + \theta_3^2 \delta_{\sigma'_v}^2\) (their Eqs. 4 and 5), where \(\delta_{CSR}\) is "cov_csr", \(\sigma_{N_{1,60}}\) is "sigma_n160", \(\sigma_{FC}\) is "sigma_fc", and \(\delta_{\sigma'_v}\) is "cov_sigmavp". Because ucla_plha integrates the ground motion variability in the hazard calculation, "cov_csr" should represent only the uncertainty in estimating CSR for a given ground motion (e.g., \(r_d\) and the stresses), not the variability of the ground motion.

Note

You cannot include keys that are not required by a given model. For example, "n160" cannot appear in a cone penetration test model entry.

"output" keys#

The "output" object specifies whether to write the PSHA and/or PLHA output to a JSON file, and whether to include disaggregation data. Including disaggregation data slows down the calculations, and should be included only if needed.

key

definition

notes

"psha"

include to output a PSHA hazard curve

optional

"pga"

array of PGA values at which to evaluate the hazard curve

required if "psha" is included

"plha"

include to output a PLHA hazard curve

optional

"fsl"

array of factor-of-safety values at which to evaluate the hazard curve

required if "plha" is included

"disaggregation"

include under "psha" or "plha" to output disaggregation data

optional

"magnitude_bin_edges"

edges of magnitude bins for disaggregation

required if "disaggregation" is included

"distance_bin_edges"

edges of distance bins for disaggregation

required if "disaggregation" is included

"epsilon_bin_edges"

edges of epsilon bins for disaggregation. Bins include their lower edge and exclude their upper edge; events outside the bins are not binned (use wide outer edges, e.g. -1e9 and 1e9, to bin all of them)

required if "disaggregation" is included

"distance_metric"

distance used for the distance bins: "default" (rjb if a ground motion model uses rjb, otherwise rrup), "rrup" (as the USGS NSHM disaggregation), or "rjb"

optional ("psha" and "plha")

"means"

true to also output "disaggregation_means": the binned contribution (%) and the mean magnitude, distance, and epsilon at each PGA, in total and, with "source_model_hazard", per source model

optional ("psha")

"outputfile"

filename for saving output (includes a copy of the inputs)

optional

Note

You can specify "plha" and its "disaggregation" object without including "psha". In this case the PSHA will still be performed internally, but its results will not be returned.

Whether or not "outputfile" is specified, the code returns a Python dictionary containing all results.

The input JSON object is saved alongside the output in "outputfile" so that inputs and outputs are always stored together. This prevents inconsistencies if the config file is modified after a run.

Full config structure#

The following shows the complete structure of a config file. Note that keys are lowercase following PEP 8 convention, but the config file is case-insensitive so N160 works equally well as n160. Optional inputs are shown with their default values where applicable.

{
   "site": {
      "latitude": 34.0,
      "longitude": -118.0,
      "elevation": 0.0,
      "vs30": 350.0,
      "measured_vs30": false,
      "z1p0": 0.05,
      "z2p5": 0.5
   },
   "constraints": {
      "dist_cutoff": 200,
      "m_min": 5.0
   },
   "source_models": {
      "fault_source_models": {
         "ucerf3_fm31": {"weight": 0.5},
         "ucerf3_fm32": {"weight": 0.5}
      },
      "point_source_models": {
         "ucerf3_fm31_grid_sub_seis":     {"weight": 0.25},
         "ucerf3_fm31_grid_unassociated": {"weight": 0.25},
         "ucerf3_fm32_grid_sub_seis":     {"weight": 0.25},
         "ucerf3_fm32_grid_unassociated": {"weight": 0.25}
      }
   },
   "ground_motion_models": {
      "ask14":  {"weight": 0.25},
      "bssa14": {"weight": 0.25},
      "cb14":   {"weight": 0.25},
      "cy14":   {"weight": 0.25}
   },
   "liquefaction_models": {
      "boulanger_idriss_2012": {
         "n160": 10.0, "fc": 5.0,
         "sigmav": 100.0, "sigmavp": 60.0, "depth": 5.0, "pa": 101.325,
         "weight": 0.25
      },
      "boulanger_idriss_2016": {
         "qc1Ncs": 80.0,
         "sigmav": 100.0, "sigmavp": 60.0, "depth": 5.0, "pa": 101.325,
         "weight": 0.25
      },
      "cetin_et_al_2018": {
         "n160": 10.0, "fc": 5.0, "vs12": 150.0,
         "sigmav": 100.0, "sigmavp": 60.0, "depth": 5.0, "pa": 101.325,
         "weight": 0.25
      },
      "moss_et_al_2006": {
         "qc": 3.0, "fs": 0.05,
         "sigmav": 100.0, "sigmavp": 60.0, "depth": 5.0, "pa": 101.325,
         "weight": 0.25
      },
      "ngl_smt_2024": {
         "ztop":    [4.5, 5.0],
         "zbot":    [5.0, 5.5],
         "qc1Ncs":  [80.0, 85.0],
         "Ic":      [1.8, 1.9],
         "sigmav":  [100.0, 110.0],
         "sigmavp": [60.0, 65.0],
         "Ksat":    [1.0, 1.0],
         "pa": 101.325,
         "weight": 0.0
      }
   },
   "output": {
      "psha": {
         "pga": [0.01, 0.02, 0.05, 0.1, 0.2, 0.5, 1.0],
         "disaggregation": {
            "magnitude_bin_edges": [5.0, 6.0, 7.0, 8.0],
            "distance_bin_edges":  [0, 25, 50, 100, 200],
            "epsilon_bin_edges":   [-3, -2, -1, 0, 1, 2, 3]
         }
      },
      "plha": {
         "fsl": [0.5, 0.75, 1.0, 1.25, 1.5, 2.0],
         "disaggregation": {
            "magnitude_bin_edges": [5.0, 6.0, 7.0, 8.0],
            "distance_bin_edges":  [0, 25, 50, 100, 200],
            "epsilon_bin_edges":   [-3, -2, -1, 0, 1, 2, 3]
         }
      },
      "outputfile": "output.json"
   }
}
